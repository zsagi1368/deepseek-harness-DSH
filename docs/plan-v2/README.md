## 4. 给执行协调者（ORCH Agent）的启动指令

1. 读 `01`、`02`、`03`、`04`、`05`，建立全局认知。
2. 在 `G:\000Github\DSH\Plan\` 下创建 `STATE.md` 状态板（格式见 05 号文档第 5 节），把 04 号文档的任务表初始化进去。
3. 按 05 号文档的组建方式拉起队伍，按 04 号文档的依赖图调度；每个任务下发对应任务书（06–09）全文 + 10 号文档。
4. 铁律：**Phase 门禁未过不得进入下一 Phase**；**任何破坏性 git 操作（force push、删分支）必须先备份并取得用户确认**；**任务完成必须写交接记录**。
5. 全程使用中文交流与写文档；代码注释与提交信息遵循 [10-质量保障与验收标准](10-质量保障与验收标准.md)。

## 5. 术语表

| 术语 | 含义 |
|---|---|
| 官方 / upstream | `deepseek-ai/deepseek-harness`（remote 名 `upstream`，已配置并 fetch 到本地） |
| fork / origin | `zsagi1368/deepseek-harness-DSH`（remote 名 `origin`） |
| DSH 分支 | 本地开发的总称；规范文档称 "ours"，运行时隔离目录 `~/.dsh-dsh` |
| 孤儿分支 | 无父提交（orphan）创建的分支，与官方历史无共同祖先 |
| 治理体系 | fork 新增的插件治理系统：PluginSpec / Registry / 三层沙箱 / 三层守卫 / CordisAdapter / 持久化 |
| 快照式导入 | 把整个工作区（含构建产物）一次性提交，破坏历史继承的开发方式（本方案废弃） |
| 三元组 | 官方 i18n 契约：`foo.md` + `foo.zh.md` + `foo.i18n.yaml`（记录两侧一致的 blob hash） |
| 重建基线 / re-anchor | 从官方最新 master 新建分支，把本地真实改动作为补丁移植过去，恢复真实祖先关系 |
| P0/P1/P2 | 问题严重级：P0 阻断（安全/数据）、P1 重要（功能缺陷）、P2 改进 |
