# 12 · 环境与工具规范

> 目标：任何 Agent/人在新机器上能一小时内进入可开发状态。

---

## 1. 硬件/系统基线

- Windows 10/11 x64（当前：win32 10.0.26200），Shell = Git Bash（所有文档命令按 Git Bash 语法）。
- 磁盘：Fork 仓库含 node_modules 约 4–6 GB 余量；网络可达 github.com（upstream+origin）与 npm registry。

## 2. 工具链版本（以官方根 package.json 的 `engines` / `packageManager` 为准，装错版本是常见翻车点）

| 工具 | 要求 | 检查 |
|---|---|---|
| Node | 官方 engines 指定版本（用 nvm-windows 管理多版本） | `node -v` |
| pnpm | 官方 packageManager 指定版本（corepack 自动启用） | `pnpm -v` |
| Git | ≥2.40（含 `--force-with-lease`、sparse 各特性）；Git Credential Manager 启用 | `git --version` |
| Python | 仅涉及 `python/` 工作时需要（pytest.ini 存在）；核心 Phase 0–5 不需要 | `python --version` |
| Linux 专属 | landlock/wine 门在 Windows 本机不可用 → 一律走 GitHub Actions（见 R-5） | — |

## 3. 目录与仓库约定

```
G:\000Github\DSH\
├── Fork\          唯一 git 仓库（工作目录；remote: origin + upstream）
├── Plan\          本套件 + STATE.md + logs\ + artifacts\（不入 our/v2，持久化在 archive 线，见 T0.5）
├── R&D\           研究资料（保留清单 + archive\）
├── CoreCode\      【处置】官方旧快照，重组完成后删除或移出备份盘（R-11 关闭后）
├── Fork-Fresh\    【处置】空目录，删除或留作破坏性试验沙盒（任何 git 实验先在这里排练）
├── TMP\           【处置】T0.5 后应只剩空壳，删除
└── dsh-guard\     独立小仓库，维持现状，不参与本次重组
```

## 4. 常用命令速查（Fork 目录内）

| 场景 | 命令 |
|---|---|
| 环境自检 | `node -v && pnpm -v && git status` |
| 安装/构建 | `pnpm install --frozen-lockfile && pnpm build` |
| 全量测试/定向 | `pnpm test` / `pnpm vitest run packages/plugins/plugins` |

## 5. Git 环境一次性配置（新机器/新代理会话先跑，03 §7 详版）

```bash
git config user.name "DSH Team"
git config user.email "dsh-team@zsagi.us.ci"
git config core.autocrlf false        # EOL 交给官方 .gitattributes（our/v2 重建后设置）
git config pull.ff only
# remote 凭据：Git Credential Manager（git config credential.helper manager）
# 首次使用：git ls-remote origin HEAD 触发登录
```

多代理并行注意：同一克隆内切换分支会互相干扰 ——**并行执行代理必须共享同一工作区时，遵守包级互斥并顺序切换分支**；若条件允许，为每个开发代理用 `git worktree add ../Fork-<role> <branch>` 建独立工作树（Fork-Fresh 之外的临时 worktree 放 `G:\000Github\DSH\Worktrees\`，事后清理）。

## 6. 新会话冷启动清单（Agent 接手时）

1. `cd G:/000Github/DSH/Fork && git status && git branch -a -vv` —— 确认在 our/v2（或 STATE.md 记录的当前分支）、工作区状态与 STATE.md 一致。
2. `source /g/000Github/DSH/.agent-env` —— 加载 GitHub 凭据（GH_TOKEN；文件在所有 git 仓库之外，**禁止**将其内容复制到任何仓库/文档/聊天）。之后 gh 与 API 调用即可用；推送走已有的 SSH 密钥。
3. 读 `Plan/STATE.md` —— 当前 Phase、任务状态、冲突区占用。
4. 读自己的角色章节（05 §4）+ 下一任务的任务书 + `10` 号文档。
5. 若 STATE.md 与实际 git 状态矛盾 → 停，报 ORCH（R-13 场景），不自行修复。
6. 开工：按 05 §6 生命周期执行，产出六节交接记录。

## 7. 已知环境坑（本项目实证）

| 坑 | 说明 | 规避 |
|---|---|---|
| 目录名含 `&`（`PluginR&D`、`R&D`） | bash 未加引号即语法错误 | 所有路径引用一律双引号 |
| `core.autocrlf=true` 全局默认 | 与官方 .gitattributes 叠加产生全树噪音 | our/v2 重建后置 false（03 §7） |
| 构建产物曾被跟踪 | 本地 build 后 git status 报数千 M | our/v2 起不再跟踪（T1.1）；看到大量 M 先怀疑产物路径而非真实改动 |
| `pnpm test --filter=<pkg>` | 语法无效（旧 CI 翻车点） | 定向测试用 `pnpm vitest run <路径>` |
| Windows 控制台长输出截断 | 大 diff/log 用后台任务落文件再 Read | 惯例：`| tail -N` 或重定向到 Plan/artifacts/ |
