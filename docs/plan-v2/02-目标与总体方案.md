# 02 · 目标与总体方案

> 前置阅读：[01-现状评估报告](01-现状评估报告.md)。本文回答"改成什么样"。

## 1. 项目定位（不变，重申）

基于官方 deepseek-harness 持续演进的增强分支："**基于官方，快速迭代，兼容生态，安全增强**"。差异化价值四件事：

1. **插件治理体系**：为官方 Cordis 插件生态叠加 Manifest 声明、三层沙箱、三层守卫、健康熔断、审批对接——"隔离优于审核"。
2. **插件管理 UI**：在官方 Web 端提供完整的插件启停/批量/preset 管理面。
3. **安全增强**：凭证加密、日志脱敏、权限加固、结果上限、命令注入防护等官方未合入的修复。
4. **分支独立运行**：与官方安装共存（独立数据目录/端口/进程名），可随时切回官方。

## 2. 核心决策（D1–D8）

| # | 决策 | 理由 | 替代方案与否决原因 |
|---|---|---|---|
| D1 | **废弃快照式孤儿分支，重建真实祖先**：新开发线 `our/v2` 从 `upstream/master`（0.1.1-rc.2）切出，本地改动以补丁方式移植 | 恢复 merge/rebase 能力是"持续跟进官方"的前提（A-1） | 就地 `merge --allow-unrelated-histories`：整树冲突不可解；继续快照对比：不可持续 |
| D2 | **旧分支全部归档不删除**：`our/base` → `archive/our-base-v1`；`master` 重建为官方历史；旧 tag/游离链保留 | 可追溯、可回滚、零丢失 | 删除旧分支：丢失唯一的历史凭证 |
| D3 | **治理体系正式化为 workspace 包**：`packages/plugins/plugins` = `@deepseek-ai/dsh-plugin-governance`，配 package.json、按官方 glob 放测试、进构建与 knip | 死代码→活代码（A-2）；沿用官方 `packages/<group>/<pkg>` 与 `@deepseek-ai/dsh-*` 命名（BRANCH-INDEPENDENCE-SPEC 亦要求保留官方 scope） | 拆 7 个子包：过度工程，先单包 |
| D4 | **与官方 Cordis 双轨兼容**：官方插件经 `CordisAdapter` 包装进入治理体系（默认 OFFICIAL 沙箱配置）；治理体系原生插件走 PluginSpec。以 plugin-compat-analysis.md 的 4 阶段路线推进，v2 只做阶段 1（adapter 可加载官方示例插件 + 双轨注册表打通） | 4 个 P0 不兼容的现实解法；"零破坏兼容官方生态"的唯一路径 | 重写官方插件体系：工程量与冲突风险不可接受 |
| D5 | **UI 接线到官方设置页**：`ui-plugin-manager` 注册进 client modules manifest + tsconfig references，作为官方 `ui-settings-plugins` 的增强区块（同页共存，不替换），API 走 host 面新增 `plugin-governance` service → `apiproxy` Remote | 遵循官方"一切皆插件/模块注册"架构（AGENTS.md）；避免与官方 UI 双头冲突 | 独立页面：入口 discoverability 差且重复官方设置入口 |
| D6 | **存储统一**：环境变量 `DSH_BRANCH_HOME`（避免与官方 `DSH_HOME` 语义冲突），默认 `~/.dsh-dsh`（对齐 BRANCH-INDEPENDENCE-SPEC）；废除 cwd 相对目录；同步更新注释 | 消除 B-3；不污染任意工作目录；与官方 DSH_HOME 不打架 | 沿用 DSH_HOME：会覆盖官方语义，破坏"共存"目标 |
| D7 | **质量基线 = 官方全套**：从 upstream 切出即自动恢复 18 个 CI workflow、lint 配置、`.gitignore/.gitattributes`；在此基础上新增 `plugin-governance.yml`（修好原来的坏 CI） | 官方门禁是免费且持续演进的质量资产（A-3/A-5 根治） | 自建精简 CI：放弃官方 14 门矩阵，得不偿失 |
| D8 | **文档收敛**：fork 改动说明集中于 `docs/dsh/`（遵守三元组 i18n 契约）；README 不整体重写，官方 README + DSH 附录；单一 CHANGELOG；R&D 过程报告归档并建 issue 映射表 | 修复 B-2/B-6，通过官方 `verify-translation-pairing` 等文档门禁 | 保留 6 份 CHANGELOG/根目录报告堆：继续失控 |

**不移植清单（backlog）**：`packages/memory`（薄且未接线，记入 backlog-001）；三个核心插件 dsh-sessions/dsh-mock/dsh-codex-shell（不在当前分支，从旧链找回后另行评估，backlog-002，对应 R&D/COMMUNITY-PLUGINS-EVALUATION 的"完全重写"策略）；`planning/` 43 份过程文档、6 份 CHANGELOG、重写版 README（D8 取代）。

## 3. 目标架构

### 3.1 分支/代码结构（重组后）

```
upstream/master (官方 0.1.1-rc.2+)
   │  fetch only，永不直接推送
   ▼
origin/master（镜像官方历史，只快进）          ← D2/D7：重建为真实历史
   │
   ▼
our/v2（DSH 开发主线，真实祖先）               ← D1：所有 fork 改动以主题分支合入
   ├── our/feat/plugin-governance   （D3/D4）
   ├── our/feat/plugin-manager-ui   （D5）
   ├── our/feat/branch-isolation    （D6）
   ├── our/fix/<bug-id>             （安全修复与 P1 缺陷，逐 bug 一分支）
   └── our/release/<version>        （发布固化）
archive/our-base-v1、archive/*       （旧线归档）
```

### 3.2 插件治理体系包内结构（`packages/plugins/plugins/`）

```
packages/plugins/plugins/                    @deepseek-ai/dsh-plugin-governance
├── package.json                             peer 依赖官方 @deepseek-ai/cordis* 相关包（对齐官方包惯例）
├── src/
│   ├── index.ts                             公共出口（spec 类型 + registry + guards + sandbox 工厂 + adapter + persistence）
│   ├── spec/index.ts                        PluginManifest / capabilities / sandbox 声明 / ID 规范化
│   ├── base/base.ts                         BasePlugin
│   ├── registry/registry.ts                 DefaultPluginRegistry（含 Cordis 双轨注册）
│   ├── guards/{load-guard,run-guard,watcher,health-guard}.ts
│   ├── sandbox/{index,inline-sandbox,worker-sandbox,process-sandbox}.ts
│   ├── compat/cordis-adapter.ts             官方插件包装（阶段 1 落地物）
│   └── persistence/plugin-persistence.ts    DSH_BRANCH_HOME 持久化（D6）
├── tests/                                   官方 vitest glob：packages/*/*/tests/**/*.spec.ts
│   ├── spec.spec.ts / registry.spec.ts / guards.spec.ts
│   ├── sandbox.spec.ts / cordis-adapter.spec.ts / persistence.spec.ts
│   └── security.spec.ts                     （合并原 security-fix*.test.ts）
└── README.md + README.zh.md + README.i18n.yaml   （三元组）
```

接线点（谁 import 它）：
- host 面：`packages/host/plugin-governance/`（新增小包）注册 Cordis service，暴露 Remote API（方法面：list/install/uninstall/enable/disable/health/preset），经官方 `apiproxy` 体系暴露给浏览器；
- client 面：`ui-plugin-manager` 经 modules manifest 加载，调 Remote API（替换全部 TODO 桩）；
- 官方 `dsh plugin` CLI 命令与 `plugin-inventory` 保持不动（只读投影继续工作）。

### 3.3 与官方架构的关系（约束，开发必须遵守）

官方 AGENTS.md 的架构铁律（对 fork 同样有效）：一切皆 Cordis 插件；注册必须 `ctx.effect()`；瀑布监听必须调 `next()`；model-visible ⟺ logged；非平凡变更附 Agent Note（`.agents/notes/`，fork 曾删该目录，重建后恢复）；包名 `@deepseek-ai/dsh-<name>`；strict TS + JSDoc；`test:coverage` 是门禁；vendored 包不动。**治理体系本身也必须以 Cordis 插件形态挂载**（即 plugin-governance host 包是一个 entry，通过 `cordis.yml`/bundle 层组合进 profile），而不是旁路单例。

### 3.4 独立运行隔离（对齐 BRANCH-INDEPENDENCE-SPEC）

| 维度 | 官方 | DSH 分支 |
|---|---|---|
| 数据目录 | `~/.dsh/` | `~/.dsh-dsh/`（`DSH_BRANCH_HOME` 可覆盖） |
| 端口 | Web 61368 / API 8000 | 61369 / 8001 |
| 进程/命令 | `dsh` | 保持 `dsh`（同一 CLI，按环境变量切换），分支专属数据全部在 DSH_BRANCH_HOME 下 |
| 包名/scope | `@deepseek-ai/*` | **相同**（仅版本后缀 `-DSH<date><letter>` 区分，见 VERSION-NAMING-SPEC） |

## 4. 版本与发布目标

- 首个重组版本：**`0.1.1-rc.2-DSH<YYYYMMDD>a`**（命名规则沿用 R&D/VERSION-NAMING-SPEC.md，基线升到官方 0.1.1-rc.2）。
- 版本唯一入口：根 package.json `scripts.version`；tag 必须打在**通过全部门禁的提交**上（修复 B-1）。
- 发布物：分支推送（origin our/v2 + master 镜像）＋ `docs/dsh/CHANGELOG` 更新。

## 5. 目标状态验收（重组完成的定义）

1. `git merge-base our/v2 upstream/master` 有输出且等于 upstream/master（真实祖先）；
2. `pnpm install && pnpm build && pnpm test` 全绿（含治理包新测试），`pnpm check:all` / `pnpm hygiene` 通过（Windows 环境按官方 Windows 门子集）；
3. 官方 18 CI workflow + 修复后的治理 CI 在 push 后全绿；
4. 一个官方示例 Cordis 插件能经 CordisAdapter 在治理体系内加载、启用、停用（阶段 1 兼容目标）；
5. Web 端设置页可见插件管理区块并能真实操作（无 TODO 桩）；
6. 无 PAT 明文（`.git/config` 与所有文档）、无 `_tmp_*`、无构建产物入库、`git status` 干净；
7. CHANGELOG 单一、issue 四套编号有映射表、README 通过 `pnpm run verify-translation-pairing`。
