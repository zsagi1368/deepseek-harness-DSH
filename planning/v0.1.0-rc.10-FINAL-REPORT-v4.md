## 二、Phase 4 新增修复详情

### Fix 1: max-tokens 截断死循环 (NEW-001) 🔴 P0

**问题**: BlockAssembler 在 max-tokens 截断时丢弃最后一个 tool-call，导致 Agent "有意图无执行" 死循环。

**RC9 状态**: assembler.ts 已实现 `truncatedToolCalls` 逻辑，但 **agent.ts 完全没有消费这个字段**。

**RC10 修复**:
```typescript
// packages/core/agent-loop/src/agent.ts:397-418
if (finish.kind === 'max-tokens') {
  if (truncatedToolCalls.length > 0) {
    // 将 truncated tool-call 重新入队，避免死循环
    const toolCalls = truncatedToolCalls.map(block => ({...}))
    this.session.append('assistant/truncated-tool-calls', {...})
    this.inbox.splice('next-step', ...)
    return { kind: 'max-tokens' }
  }
  return { kind: 'max-tokens' }
}
```

**验证**: 
- ✅ assembler.ts: `truncatedToolCalls` getter 已暴露
- ✅ agent.ts: step() 方法已消费 truncatedToolCalls
- ✅ types.ts: TruncatedToolCall 接口已定义
- ✅ 测试通过: `pnpm test --filter=@deepseek-ai/dsh-agent-loop`

### Fix 4: 中文 Token 估算修正 (NEW-004) 🟡 P2

**问题**: `CHARS_PER_TOKEN=*** 对中文低估 3-4x。

**RC10 修复**:
```typescript
// packages/llm/token-meter/src/estimate.ts:27-76
function countCJKChars(text: string): number { ... }
function estimateTextTokens(text: string): number {
  const cjkCount = countCJKChars(text)
  const latinCount = text.length - cjkCount
  return cjkCount + Math.ceil(latinCount / CHARS_PER_TOKEN)
}
```

**验证**: 
- ✅ CJK 检测逻辑已实现
- ✅ estimateContent() 已使用 estimateTextTokens()
